# Qwen3.8-27B on AMD MI300X: Dynamo vs llm-d

This directory contains the reproducible assets for the 2026-08-29 RunPod
experiment comparing vLLM behind Dynamo and llm-d in aggregate and true
prefill/decode-disaggregated modes.

## Benchmark matrix

- Model: `Qwen/Qwen3.8-27B`
- Hardware: one AMD Instinct MI300X (192 GiB) per worker, two workers per system
- Shapes: ISL/OSL `1024/8192`, `8192/8192`, and `8192/1024`
- Concurrency: `1`, `4`, and `16`
- Fixed lengths: random range ratio `0.0`, `--ignore-eos`, seed `42`
- API: streaming OpenAI chat completions

`run_qwen38_pareto.sh` is resumable: a point is skipped only when its result
JSON already exists and is non-empty. `aggregate_qwen38_results.py` rejects a
point if any request failed or the completed-request count differs from the
requested count.

## True P/D gates

A run is called disaggregated only after all of these are observed:

1. Distinct processes have complementary prefill and decode roles.
2. Both vLLM workers use `MoRIIOConnector` with producer/consumer KV roles.
3. The control plane selects both typed workers for one request.
4. One `tx...` transfer ID is present on both legs.
5. Worker logs show a MoRI handshake and completed KV transfer.
6. The response is generated by decode after remote prefill; killing prefill
   causes the validation request to fail rather than silently falling back.

### Dynamo

The ROCm vLLM image provides MoRI-IO, while the tested Dynamo release only
registers NIXL and Mooncake coordination protocols. Mooncake's runtime is not
installed in that ROCm image. `dynamo-qwen38-mi300x/moriio_protocol.py` is the
small deployment overlay that emits the same MoRI WRITE-mode metadata used by
llm-d. `install_moriio_overlay.sh` installs it and runs a wire-contract test.
Dynamo workers discover each other through etcd and advertise typed prefill and
decode endpoints; the frontend is the only benchmark target.

### llm-d

The EPP configuration uses file discovery with explicit `role=prefill` and
`role=decode` labels and `always-disagg-pd-decider`. The decode endpoint exposed
to Envoy is the llm-d P/D sidecar, not raw vLLM. The sidecar injects the decode
host, handshake/notify ports, DP/TP ranks, and shared transfer ID into the
prefill and decode legs.

## Files

- `run_qwen38_pareto.sh`: matched benchmark sweep
- `aggregate_qwen38_results.py`: strict result normalizer
- `dynamo-qwen38-mi300x/`: Dynamo workers, frontend, and MoRI overlay
- `llmd-qwen38-mi300x/`: vLLM workers, EPP, Envoy, and P/D sidecar configuration

Ephemeral pod IDs and public SSH ports are intentionally excluded. Private IPs
in the example configs match the recorded run and must be updated if RunPod
allocates a different bridge network.
